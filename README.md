## What each advisory contains

Summary · vulnerable component · attack vector and prerequisites · **full proof of concept** (environment, reproduction steps, measured result, positive/negative controls) · impact · preconditions · remediation · prior-art check · references · credits · disclosure status.

## Common pattern

All findings share the same class of defect: an Android component (`Activity`, `Service`, `BroadcastReceiver` or `ContentProvider`) that is exported without a permission gate, so any application installed on the device — holding **no runtime permissions at all** — can drive it and cross a trust boundary into the victim application's UID. The dominant CWE is [CWE-926](https://cwe.mitre.org/data/definitions/926.html) (Improper Export of Android Application Components).

## Provenance and limitations

Each advisory records the artifact hash that was verified, the exported declaration read from the shipped manifest, the code path with file/line citations, and a reproduction on a stock Android 13 (API 33) emulator. Where a project has a security contact the advisory states the upstream status that was verified at the time of writing; several of the affected projects are unmaintained or archived, and for those no fix is available. Affected-version ranges are limited to the builds actually verified. Anything that could not be verified is explicitly marked as such in the text.
