# Exported installer activity in AndBible unzips caller archives into its private storage

| | |
|---|---|
| **CVE ID** | *pending* — requested; MITRE CNA-LR tracking number `CAN-2026-2053059` |
| **Package** | `net.bible.android.activity` |
| **Product** | AndBible: Bible Study |
| **Affected versions** | 1111 (affected) |
| **Weakness** | CWE-926 (Improper Export of Android Application Components) |
| **Platform** | Android |
| **Published** | 2026-10-11 |
| **Internal ID** | W6-H11-03 |

## Summary

AndBible: Bible Study (net.bible.android.activity) version 1111 for Android: exported module/study-pad installer that unzips a caller-supplied archive into the victim's own storage; the two extractors join raw `ZipEntry.getName` to the destination dir while the manifest gate that protects them matches only a prefix

**Vulnerable component:** shipped manifest of sha256 OK `e6fa5ec232b2d7dd…` vc=1111, SRC-PAIR apk vc=1111 <-> src vc=1111 [same-entry]; 71 components, exported-permissionless=11; the queue's entry `net.bible.android.view.activity.installzip.In [...] AGE(maxSdk 28), INTERNET, WAKE_LOCK, FOREGROUND_SERVICE*, POST_NOTIFICATIONS, targetSdk 35 (`app/build.gradle.kts:180`)

## Attack vector and prerequisites

Any app can send the archive (via `EXTRA_STREAM`, served by its own provider). No runtime permission and no user interaction. Each entry must carry one of the module prefixes the gate accepts (`mods.d/`, `modules/`, `epub/`, `mysword/`, `mybible/`, `esword/`) or it is rejected wholesale - so the primitive is a constrained write, not arbitrary file placement.

## Proof of concept

Environment: API 33 emulator, `adb unroot` + `id` asserted `uid=2000(shell)` before and after each action; ground truth read as root from the device, not from any probe UI; probe with no permissions. - Case 1 (`ACTION_SEND`, module zip): entries `mods.d/rv2A<tag>.conf`, `modules/rv2B<tag>.dat`, `modules/../rv2C<tag>.txt`, `modules/../../rv2D<tag>.txt`, `modules/../../../rv2E<tag>.txt`, `modules/../../../../rv2F<tag>.txt`. The victim ran `InstallZip` unattended (START to writes, no dialog, no input). The destination resolved to `/storage/emulated/0/Android/data/net.bible.android.activity/files`; `files/mods.d/…`, `files/modules/rv2B…`, `files/rv2C…` landed in scope, and **`Android/data/net.bible.android.activity/rv2D…txt` landed OUTSIDE the extraction root** with the attacker's bytes. Deeper escapes (rv2E/rv2F) failed with `EACCES` - the app does no containment at all; only the OS sandbox bounds the reach. - Case 2 / 2b (`ACTION_VIEW`, a `STUDYPAD_EXPORT` zip): no consent dialog appeared before extraction; the victim's own log shows writes for every entry, including the traversal ones. Root ground truth: `files/backup/unzip/rv2sp…txt` (written before any question), escapes to `files/backup/rv2spU1…` and `files/rv2spU2…`, **`/data/data/net.bible.android.activity/rv2spU3…xml` at the root of the victim's private data tree**, and **`/data/data/net.bible.android.activity/shared_prefs/rv2spU4…xml`** - an arbitrary-named file planted next to the victim's real preferences. `unzipInputStream` has no exists/overwrite protection, so overwriting existing private files is the same primitive. (The victim crashed after extraction because the zip carried no bookmarks database; the writes had already landed.) - Reverse controls: with no `EXTRA_STREAM` the onCreate coroutine NPEs and nothing is extracted; with a zip whose only entry fails the prefix gate nothing is extracted. The final root sweep found 13 planted markers, all with attack-case tags and none with a control tag.

## Preconditions / configuration

Attacker: an application installed on the device with no runtime permissions. Victim: none beyond installation of the application.

## Remediation

No fix released by the upstream project as of 2026-09-27; the vulnerable declaration is unchanged on the default branch commit that was checked. Recommended remediation: add an android:permission (or set android:exported="false" where external callers are not intended) to the affected component so that only the vendor's own applications can reach it.
