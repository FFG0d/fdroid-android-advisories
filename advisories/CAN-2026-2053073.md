# Exported headless activities in MyBrain plant caller text into the user's notes

| | |
|---|---|
| **CVE ID** | *pending* — requested; MITRE CNA-LR tracking number `CAN-2026-2053073` |
| **Package** | `com.mhss.app.mybrain` |
| **Product** | com.mhss.app.mybrain |
| **Affected versions** | 3.1.0 (affected) |
| **Weakness** | CWE-926 (Improper Export of Android Application Components) |
| **Platform** | Android |
| **Published** | 2026-10-11 |
| **Internal ID** | W6-H37-01 |

## Summary

com.mhss.app.mybrain version 3.1.0 for Android: exported permission-less *headless* activities that plant caller-supplied title+body into the user's own notes (and, by the same code path, tasks and bookmarks) with no confirmation, no caller check and nothing drawn on screen Impact ceiling: Ceiling: the write lands in the app's own database and the attacker gets no read-back channel, no code execution and no privilege escalation; only `AddNoteFromShareActivity` was driven dynamically - `AddTaskFromShareActivity` and `SaveBookmarkActivity` are the same shape in the same manifest and source tree and are reported as static siblings, not as separately measured claims. Impact as measured: a zero-permission app silently plants attacker-chosen notes (title + body) into the user's personal knowledge base

## Attack vector and prerequisites

Precondition: none beyond installation - no account, no preference gate, no SAF grant, no wizard

## Proof of concept

Reporter-verified proof of concept, reproduced on a stock Android 13 (API 33) emulator cold-booted with -wipe-data. The attacker is an application installed on the same device holding no runtime permissions; the victim is the shipped build under test. Prerequisites: Precondition: none beyond installation - no account, no preference gate, no SAF grant, no wizard Shipped manifest (read with `aapt2 dump xmltree` on the installed APK) declares three `Theme.NoDisplay` activities with `android:exported="true"` and no permission. `AddNoteFromShareActivity.kt:21-47`: `onCreate` takes `ACTION_SEND` + `text/plain`, reads `EXTRA_TEXT` (`:25`) and `EXTRA_SUBJECT` (`:26`), and for a non-blank body calls `upsertNote(Note(title=SUBJECT, content=TEXT, createdDate=now, updatedDate=now))` (`:30-37`) on `Dispatchers.IO`; the only other effect is a Toast (`:40-44`). `SaveBookmarkActivity.kt:16-41` is the same shape with `AddBookmark(Bookmark(url=EXTRA_TEXT, title=EXTRA_SUBJECT))` gated only by `url.isValidUrl`. Pass 1 (emulator-5562, cve_fresh33_5, API 33; attacker `com.cvefind.probe2`, uid 10178, INTERNET only): explicit `SEND text/plain` with `EXTRA_TEXT=MBRAIN-NOTE-054509` / `EXTRA_SUBJECT=MBRAIN-TITLE-054509` produced `ActivityTaskManager: START u0 {act=android.intent.action.SEND typ=text/plain cmp=com.mhss.app.mybrain/com.mhss.app.presentation.AddNoteFromShareActivity clip={text/plain {T(18)}} (has extras)} from uid 10178`; the read-back is taken through the app's own UI (its Notes list - the database is private and the build is not debuggable, so the UI is the only honest channel) and shows both `text="MBRAIN-TITLE-054509"` and `text="MBRAIN-NOTE-054509"`. Control - the identical explicit SEND to the same component with no `EXTRA_TEXT` - produced its own START line but left the Notes list unchanged. Pass 2 (emulator-5560, cve_fresh33_4; attacker `com.cvefind.probe`, uid 10180, own build/install): `EXTRA_TEXT=MBRAIN-P2-055639` / `EXTRA_SUBJECT=MBRAIN-P2T-055639`, `START u0 {...} from uid 10180`, and shows `text="MBRAIN-P2T-055639"` (title) and `text="MBRAIN-P2-055639"` (body). Evidence

## Impact

Ceiling: the write lands in the app's own database and the attacker gets no read-back channel, no code execution and no privilege escalation; only `AddNoteFromShareActivity` was driven dynamically - `AddTaskFromShareActivity` and `SaveBookmarkActivity` are the same shape in the same manifest and source tree and are reported as static siblings, not as separately measured claims. Impact as measured: a zero-permission app silently plants attacker-chosen notes (title + body) into the user's personal knowledge base

## Preconditions / configuration

Attacker: an application installed on the device with no runtime permissions. Victim: none beyond installation - no account, no preference gate, no storage grant, no wizard.

## Remediation

No fix released by the upstream project as of 2026-09-27; the vulnerable declaration is unchanged on the default branch commit that was checked. Recommended remediation: add an android:permission (or set android:exported="false" where external callers are not intended) to the affected component so that only the vendor's own applications can reach it.
