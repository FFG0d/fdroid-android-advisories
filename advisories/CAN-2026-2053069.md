# Exported settings importer in Forkyz applies a caller-supplied JSON to the victim's configuration

| **Product** | Forkyz |
| **Affected versions** | 8500000 (affected) |

| **Platform** | Android |
| **Published** | 2026-10-11 |
| **Internal ID** | W6-H27-01 |

## Summary

Forkyz (app.crossword.yourealwaysbe.forkyz) version 8500000 for Android: Forkyz (app.crossword.yourealwaysbe.forkyz) versionCode 8500000, Android: the shipped `ForkyzSettingsImporter` activity is exported with no permission and applies a caller-supplied settings JSON to the victim app with no confirmation and no caller check: the intent URI (VIEW data or SEND EXTRA_STREAM) is fed to `ForkyzSettings.importSettings`, parsed, and applied key-by-key through `doExportImport` (`androidApp/src/main/AndroidManifest.xml:94-105`, `ForkyzSettingsImporter.kt:43-76`, `ForkyzSettings.kt:2125-2135`). Measured effect: the victim's Storage Location setting is changed to a URI string chosen by the caller and stored without validation. Impact ceiling: A locally installed app can, with no user interaction, change the victim app's stored configuration - measured on the Storage Location setting, which is rewritten to a caller-supplied URI string without validation (the app's own screen then displays the attacker-named authority as its current storage root). This is an integrity breach of the victim's settings; if the victim later trusts the injected location for import or export, follow-on effects are possible but were not measured. Ceiling: settings-state manipulation only; no code execution, no confidentiality breach, and no effect on data outside the victim app's own configuration is claimed.

## Attack vector and prerequisites

Any app can send `ACTION_SEND` with type `application/json` and `EXTRA_STREAM` pointing at a file served by its own provider, naming the importer component explicitly. No runtime permission, no user interaction, no prior state. An `ACTION_VIEW` leg with the same JSON works too. The MIME type must be `application/json` (a `text/plain` send does not match the filter).

## Proof of concept

Environment: API 33 AVD, `-wipe-data` cold boot; `uid=2000(shell)` asserted before every action; probe `com.rv2.w6h2701` with an empty requested-permission list (uid 10175). Ground truth: root reads of the victim's data directory, comparing the tree and decoding `files/datastore/settings.pb` field by field (the app keeps settings in Jetpack DataStore; its `shared_prefs` stays an empty map). - Baseline: victim launched once then force-stopped; no `settings.pb`; `shared_prefs` an empty map. - Attack: one `ACTION_SEND` of a payload naming `storageLocation=SL_EXTERNAL_SAF` plus six `saf*Uri` values pointing at URIs of the attacker's choosing. The importer's window creates and destroys itself (logcat: `Displayed ...ForkyzSettingsImporter` then `Duplicate finish request` then a toast) with no user interaction at any point. Ground truth: `settings.pb` created, and protobuf decoding shows fields 91-96 carrying all six attacker URIs and field 116 = 1 (`SL_EXTERNAL_SAF`). The same import repeated with different values overwrites all six fields (reverse run), so the storage location is a caller-controlled string that round-trips through the app's enum and persists. - Partial-JSON arm: individual keys also land (`customDailyTitle`, `customDailyUrl`, `fullScreen`, `dlOnStartup`, `disabledDownloaders` were all written), while an invalid `applicationTheme` literal is silently ignored - which is also the explanation of the earlier "no visible change" observation for those keys: they do persist, the first pass simply looked in the wrong place. - Controls: a truncated JSON raises `JSON error importing settings` and leaves the DataStore byte-identical; a send with no `EXTRA_STREAM` starts and immediately finishes with no change; a `text/plain` send never reaches the importer (the package manager resolves it to the app's main activity only); a JSON with all seven keys but `storageLocation=GARBAGE` runs through the UI flow and toasts while leaving the file byte-identical.

## Preconditions / configuration

Attacker: an application installed on the device with no runtime permissions. Victim: none beyond installation of the application.

## Remediation

No fix released by the upstream project as of 2026-09-27; the vulnerable declaration is unchanged on the default branch commit that was checked. Recommended remediation: add an android:permission (or set android:exported="false" where external callers are not intended) to the affected component so that only the vendor's own applications can reach it.
