# Exported activity in OMN interpolates a page name into a javascript URL run in its own WebView

| | |
|---|---|
| **CVE ID** | *pending* — requested; MITRE CNA-LR tracking number `CAN-2026-2053064` |
| **Package** | `net.basov.omn.fdroid` |
| **Product** | Open Markdown Notes (OMN) |
| **Affected versions** | 3400 (affected) |
| **Weakness** | CWE-79 (Improper Neutralization of Input During Web Page Generation ('Cross-site Scripting')) |
| **Platform** | Android |
| **Published** | 2026-10-11 |
| **Internal ID** | W6-H14-09 |

## Summary

Open Markdown Notes (OMN) (net.basov.omn.fdroid) version 3400 for Android: caller-supplied page name interpolated unescaped into a `javascript:` payload that the app then runs in its own WebView, which has an `addJavascriptInterface` bridge — attacker-chosen script executing with the victim app's file-writing bridge methods, unattended Impact ceiling: Code execution or injection in victim app context

## Attack vector and prerequisites

Any app can send `ACTION_SEND` (`text/plain`) with an `EXTRA_TEXT` note; no runtime permission, no user interaction, no prior state. One small precondition, measured: the text must begin with the app's own header (`OMNotesVersion: `) or carry a `Subject` line for the import path to be taken. The page name must avoid `:` `#` `?` so it survives `setPageName`'s truncation - the payload used here does.

## Proof of concept

Environment: API 33 AVD, `-wipe-data` cold boot; `uid=2000(shell)` asserted immediately before the run; the probe (`com.rv2.probe.w6h1409`) requests no permissions at all (empty requested and runtime permission sections). Victim uid 10174, probe uid 10176. Ground truth read as root from the victim's storage. - Baseline: `md/{default,bookmarks}` only; **`html/` did not exist**. - Attack (single action, no interaction): the probe sends one `ACTION_SEND` `text/plain` carrying a note whose header page name is `/p';Android.saveHTML('OMNW6H1409MKR9f3ac2','/default/Welcome','t');console.log('W6H14JSRAN9f3ac2');//` In the victim process the injected `console.log` then executes inside the victim's WebView - logged twice by the victim's own `WebChromeClient` (`W6H14JSRAN9f3ac2 -- From line: 1 of`), because `saveHTML` fires `REDISPLAY_PAGE` and the page is re-rendered - and the victim's own bridge writes `html/default/Welcome.html` (absent at baseline; sha256 `7adc7668fb064b4696279207ef8f2239d0acf5c46fe0a53d4b35f31fae1ed62e`) containing the attacker's marker `OMNW6H1409MKR9f3ac2` verbatim in the page body. That marker string exists nowhere in the app or the probe except as the injected JS argument, and the only writer of that file is the victim's `WebViewJSCallback.saveHTML` via `FileIO.saveHTML` - so the attribution to attacker-executed script is direct. - Control (same caller, same action, same code path, benign page name `/benign9f3ac2`): the page imports and renders normally (`md/incoming/benign9f3ac2.md`, `html/incoming/benign9f3ac2.html`), zero occurrences of the payload markers in logcat, and `html/default/Welcome.html` sha256 unchanged. The effect therefore comes from the unescaped quote interpolation, not from the import path itself.

## Preconditions / configuration

Attacker: an application installed on the device with no runtime permissions. Victim: the imported text must begin with the application's own header line so that the import path is taken.

## Remediation

No fix released by the upstream project as of 2026-09-27. Recommended remediation: escape values before interpolating them into JavaScript and restrict what the WebView bridge exposes.
