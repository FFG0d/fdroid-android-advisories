# Exported holiday importer in Arbeitszeiterfassung2 writes caller ICS data into the victim database

| **Platform** | Android |
| **Published** | 2026-10-11 |

## Summary

Working Time Account (askanimus.arbeitszeiterfassung2) for Android: Arbeitszeiterfassung2 (`askanimus.arbeitszeiterfassung2`): exported holiday import writes caller ICS directly into the victim DB — `feiertage.ImportActivity` is exported, permission-less, `Theme.NoDisplay`, and accepts `SEND`/`VIEW` on content URIs with `text/calendar`. - `ImportActivity.java:55-110` reads `EXTRA_STREAM` or `getData`, checks only the MIME type, opens the holiday database, calls `FeiertageIcsImport` and `FeiertageListeImport`, then navigates to MainActivity. There is no confirmation and no caller check Impact ceiling: The victim must have completed first-run setup so the main flow does not bounce back to onboarding; no attacker permission or user interaction is required. - A zero-permission app can add holiday entries to the user's work-time database. No read of the database to the attacker and no code execution is claimed

## Attack vector and prerequisites

Precondition: none beyond installation (the work-time database is created on first launch). No runtime permission and no user interaction; the caller supplies the archive.

## Proof of concept

Reporter-verified proof of concept, reproduced on a stock Android 13 (API 33) emulator cold-booted with -wipe-data. The attacker is an application installed on the same device holding no runtime permissions; the victim is the shipped build under test. Prerequisites: The victim must have completed first-run setup so the main flow does not bounce back to onboarding; no attacker permission or user interaction is required. - A zero-permission app can add holiday entries to the user's work-time database. No read of the database to the attacker and no code execution is claimed Setup state: after the victim created its default prefs and database, `init_fin=true` was set in the victim's own preferences, equivalent to completing the setup wizard. This is a victim-state precondition, not an attacker capability. - Pass 1: emulator-5558, attacker `com.cvefind.probe2` uid 10220. The probe sent its own ICS URI with marker `ARBEIT-P1-MARK-233238`; the victim DB's `feiertage` table gained `1|2026|1|1|ARBEIT-P1-MARK-233238`. - Pass 2: emulator-5560, attacker `com.cvefind.probe` uid 10174. The same flow added `1|2026|2|2|ARBEIT-P2-MARK-233327`. A control with identical bytes but MIME `text/plain` added no row, confirming the type gate and that the write was driven by the ICS import. - Evidence

## Impact

The victim must have completed first-run setup so the main flow does not bounce back to onboarding; no attacker permission or user interaction is required. - A zero-permission app can add holiday entries to the user's work-time database. No read of the database to the attacker and no code execution is claimed

## Preconditions / configuration

Attacker: an application installed on the device with no runtime permissions. Victim: none beyond installation - the work-time database is created on first launch.

## Remediation

No fix released by the upstream project as of 2026-09-27; the vulnerable declaration is unchanged on the default branch commit that was checked. Recommended remediation: add an android:permission (or set android:exported="false" where external callers are not intended) to the affected component so that only the vendor's own applications can reach it.

## Prior art

NVD, OSV and the upstream project's advisory and issue trackers were queried for this package and mechanism at verification time: no matching entry was found, and the upstream code still ships the same declaration where it was checked.
