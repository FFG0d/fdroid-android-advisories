# Exported activity in Vokibot replays a user automation from a caller-chosen trigger id

|---|---|

| **Published** | 2026-10-11 |

## Summary

Voki Bot (net.canvoki.vokibot) for Android: Vokibot (`net.canvoki.vokibot`): exported `ShortcutDispatchActivity` replays a user's automation from a caller-chosen trigger id — `net.canvoki.vokibot.shortcut.ShortcutDispatchActivity` is exported with no permission and handles `net.canvoki.vokibot.ACTION_SHORTCUT_TRIGGER` plus the caller-controlled `TRIGGER_ID` extra. - The dispatcher calls `Automation.executeByTrigger(...)`, which loads every automation with the matching `triggerId` and executes each bound command (`Automation.kt:59-84`). There is no caller check, no confirmation, and no user interaction Impact ceiling: A trigger and automation must already exist in the victim's repository; their ids are not secret. The attacker needs no permission and no user interaction for replay. - The measured effect is unattended execution of the user's automation (a privileged `startActivity` from the victim uid). Other command types can broadcast, start services, or change settings

## Attack vector and prerequisites

Precondition: an automation with a trigger id must already exist in the victim's repository. No runtime permission and no user interaction; the caller supplies the trigger id.

## Proof of concept

Reporter-verified proof of concept, reproduced on a stock Android 13 (API 33) emulator cold-booted with -wipe-data. The attacker is an application installed on the same device holding no runtime permissions; the victim is the shipped build under test. Prerequisites: A trigger and automation must already exist in the victim's repository; their ids are not secret. The attacker needs no permission and no user interaction for replay. - The measured effect is unattended execution of the user's automation (a privileged `startActivity` from the victim uid). Other command types can broadcast, start services, or change settings Seed: a `trigger_shortcut`, a `launch_activity` command targeting `com.android.settings/.Settings`, and an automation linking them were installed in the victim's own `files/repodata` before each pass. This models a normal user's existing automation; the seed is not an attacker capability. - Pass 1: emulator-5558, attacker `com.cvefind.probe2` uid 10220. The probe started the exported dispatch activity with `TRIGGER_ID=VOKI_TRIGGER`; the victim logged `Automation.executeByTrigger: Dispatching 1 automation(s)` and Android launched Settings from the victim uid 10221. A `BAD_TRIGGER` control produced no Settings launch. - Pass 2: emulator-5560 (`cve_fresh33_4`), attacker `com.cvefind.probe` uid 10174. The same flow caused victim uid 10180 to execute the automation and launch Settings. - Evidence

## Preconditions / configuration

Attacker: an application installed on the device with no runtime permissions. Victim: an automation with a trigger id must already exist in the application's own repository.

## Remediation

No fix released by the upstream project as of 2026-09-27; the vulnerable declaration is unchanged on the default branch commit that was checked. Recommended remediation: add an android:permission (or set android:exported="false" where external callers are not intended) to the affected component so that only the vendor's own applications can reach it.
