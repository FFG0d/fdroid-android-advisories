# Normal-level read permission on the Citrine content provider exposes the user's Nostr event store

| | |
|---|---|
| **CVE ID** | *pending* — requested; MITRE CNA-LR tracking number `CAN-2026-2053098` |
| **Package** | `com.greenart7c3.citrine` |
| **Product** | Citrine |
| **Affected versions** | 62 (affected) |
| **Weakness** | CWE-926 (Improper Export of Android Application Components) |
| **Platform** | Android |
| **Published** | 2026-10-11 |
| **Internal ID** | W6-P07 |

## Summary

Citrine (com.greenart7c3.citrine) version 62 for Android: `android:readPermission` = `READ_EVENTS`, declared `protectionLevel="normal"` -> cross-app read of the user's whole Nostr event store by any installer; `auth_pubkey` is a caller-supplied URI query parameter, never authenticated

**Vulnerable component:** `provider.CitrineContentProvider`, authority `com.greenart7c3.citrine.provider`

## Attack vector and prerequisites

Any app that declares the normally-granted `READ_EVENTS` permission can query the exported provider for the user's whole event store; `auth_pubkey` is a caller-supplied URI parameter and is never authenticated. No user interaction and no prior state beyond holding that normal-level permission.

## Preconditions / configuration

Attacker: an application installed on the device with no runtime permissions. Victim: none beyond installation - the read permission is normally granted to any installer.

## Remediation

No fix released by the upstream project as of 2026-09-27; the vulnerable declaration is unchanged on the default branch commit that was checked. Recommended remediation: add an android:permission (or set android:exported="false" where external callers are not intended) to the affected component so that only the vendor's own applications can reach it.
