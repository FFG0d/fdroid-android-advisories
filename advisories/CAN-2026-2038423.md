## Summary

li.klass.fhem version 2.4.1 for Android: exported entry → caller string → outbound request built from caller input and the response is delivered back to the caller: arbitrary FHEM home-automation command executed with the victim's stored server credentials

**Vulnerable component:** `.service.intent.SendCommandIntentService` (`android:exported="true"`, no permission) + `.activities.FHEMUrlActivity` (no `exported` attr + VIEW/BROWSABLE `fhem://` filter + targetSdk<31 ⇒ implicit export)

## Attack vector and prerequisites

Any app can start the exported `.service.intent.SendCommandIntentService` (action `li.klass.fhem.constants.Actions.EXECUTE_COMMAND`) with a caller-chosen `COMMAND` extra plus a caller-supplied `RESULTRECEIVER`, or send a `fhem://` VIEW/BROWSABLE URI to `.activities.FHEMUrlActivity`. No runtime permission, no user interaction, no prior state. Precondition: the victim must have configured an FHEM server (the app's own normal state), otherwise the request is routed to a dummy connection and nothing leaves the device.

## Preconditions / configuration

Attacker: an application installed on the device with no runtime permissions. Victim: an FHEM server configured in the application (its own normal operating state); otherwise the request is routed to a dummy connection and nothing leaves the device.

## Remediation

No fix released by the upstream project as of 2026-09-27; the vulnerable declaration is unchanged on the default branch commit that was checked. Recommended remediation: add an android:permission (or set android:exported="false" where external callers are not intended) to the affected component so that only the vendor's own applications can reach it.
