# Exported headless activity in FeedEx forces the victim service to fetch a caller URL

## Summary

Handy Reading (ru.yanus171.feedexfork) for Android: FeedEx Fork (`ru.yanus171.feedexfork`): exported NoDisplay activity forces the victim service to fetch a caller URL — `activity.LoadLinkLaterActivity` is exported, permission-less, themed `Theme.NoDisplay`, and accepts `SEND text/plain` (manifest lines 128-134). - The shipped dex `onCreate` reads `EXTRA_TEXT`, extracts the first HTTP URL with `HtmlUtils.HTTP_PATTERN`, and calls `FetcherService.StartServiceLoadExternalLink(url, label, false, null)`; no caller check or confirmation runs Impact ceiling: The attacker needs no permission, setup, or user interaction; the URL can point to any network location reachable by the victim. - The measured primitive is unattended victim-side fetching plus queue-state insertion. No read-back to the attacker and no code execution are claimed

## Attack vector and prerequisites

Precondition: none beyond installation. No runtime permission and no user interaction; the caller names the URL to fetch.

## Proof of concept

Pass 1: emulator-5558, attacker `com.cvefind.probe2` uid 10220. The probe sent `Load http://127.0.0.1:8766/FEED-P1B-MARK-234553 now`; the victim service added that URL to its `entries` table and issued `GET /FEED-P1B-MARK-234553` to the host-controlled server. - Pass 2: emulator-5560, attacker `com.cvefind.probe` uid 10174. The same flow added `http://127.0.0.1:8766/FEED-P2-MARK-234245` and produced the matching HTTP request. - Control: on a fresh 5560 state, `NOURL-CONTROL` produced no database row and no HTTP request.

## Preconditions / configuration

Attacker: an application installed on the device with no runtime permissions. Victim: none beyond installation of the application.

## Remediation

No fix released by the upstream project as of 2026-09-27; the vulnerable declaration is unchanged on the default branch commit that was checked. Recommended remediation: add an android:permission (or set android:exported="false" where external callers are not intended) to the affected component so that only the vendor's own applications can reach it.
