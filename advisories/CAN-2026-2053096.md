# AIDL file-read service in MAXS Fileread returns any file readable by the module uid

| | |
|---|---|
| **CVE ID** | *pending* — requested; MITRE CNA-LR tracking number `CAN-2026-2053096` |
| **Package** | `org.projectmaxs.module.fileread` |
| **Product** | MAXS Module FileRead |
| **Affected versions** | 27 (affected) |
| **Weakness** | CWE-22 (Improper Limitation of a Pathname to a Restricted Directory ('Path Traversal')) |
| **Platform** | Android |
| **Published** | 2026-10-11 |
| **Internal ID** | W6-P02+P03 |

## Summary

MAXS Module FileRead (org.projectmaxs.module.fileread) version 27 for Android exposes an exported AIDL service whose readFileBytes(String) method takes a caller-supplied absolute path with no validation, turning the module into a read proxy for everything its own uid can read (the module holds READ_EXTERNAL_STORAGE). The manifest guard on the service is USE_FILEREAD at protectionLevel=normal, a level held by any installer, so a zero-permission application can bind the service and read files outside its own sandbox. Impact ceiling: unauthorized read of files readable by the module's uid; no write path, no code execution and no privilege escalation is claimed.

## Attack vector and prerequisites

Any app can bind the module's exported AIDL services and call `readFileBytes(String)` with an absolute path; the only guard is `USE_FILEREAD`, declared `protectionLevel=normal`, i.e. held by every installer. No runtime permission beyond the guard, no user interaction. The module's uid holds READ_EXTERNAL_STORAGE, so everything it can read is readable through it.

## Preconditions / configuration

Attacker: an application installed on the device with no runtime permissions. Victim: none beyond installation - the guard is a normal-level permission held by every installer.

## Remediation

No fix released by the upstream project as of 2026-09-27; the vulnerable code path is unchanged on the default branch commit that was checked. Recommended remediation: canonicalise the caller-supplied path and confine it to the intended directory before opening it, and validate the identity of the caller rather than trusting a normal-level permission.
