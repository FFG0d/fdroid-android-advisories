# Exported StreamProvider in Ghost Commander reads and writes files via a caller-decoded file URI

|---|---|

| **Package** | `com.ghostsq.commander` |
| **Product** | Ghost Commander |
| **Affected versions** | 479 (affected) |

| **Platform** | Android |
| **Published** | 2026-10-11 |
| **Internal ID** | W6-H58-01 |

## Summary

Ghost Commander (com.ghostsq.commander) version 479 for Android: Ghost Commander (`com.ghostsq.commander`): exported, permission-less `StreamProvider` accepts a caller-decoded `file:` URI for read/write — `StreamProvider` is `android:exported="true"` at authority `com.ghostsq.commander.StreamProvider` with no permission (manifest line 230-232 of vc 479). - `openFile` selects `openProxy` on API >= 26. `QP` mode decodes the caller's base64 `URI` query parameter; when that decoded URI has scheme `file`, `openLocalFile` constructs `new File(decodedUri.getPath)` and opens it with the caller's mode. `CA` mode stores and replays adapter items, while `QP` is directly caller-controlled Impact ceiling: The attacker needs only the authority; on API 26+, `QP?URI=<base64url(file: URI)>` reaches any existing file the Ghost Commander uid can read or write. - The measured primitive is read/write in the victim's private files directory. No code execution or privilege escalation is claimed

## Attack vector and prerequisites

Precondition: none beyond installation. No runtime permission and no user interaction; the caller supplies the base64 `URI` and the access `mode`.

## Proof of concept

Reporter-verified proof of concept, reproduced on a stock Android 13 (API 33) emulator cold-booted with -wipe-data. The attacker is an application installed on the same device holding no runtime permissions; the victim is the shipped build under test. Prerequisites: The attacker needs only the authority; on API 26+, `QP?URI=<base64url(file: URI)>` reaches any existing file the Ghost Commander uid can read or write. - The measured primitive is read/write in the victim's private files directory. No code execution or privilege escalation is claimed Pass 1: emulator-5558, attacker `com.cvefind.probe2` uid 10220. A `QP` URI whose `URI` parameter decoded to `file:///data/data/com.ghostsq.commander/files/GCSTREAM-P1-MARK-230709.txt` wrote 23 attacker bytes through `openOutputStream`, then read the same path back as 23 bytes. Direct `selfRead` from the probe failed as expected. - Pass 2: emulator-5560 (`cve_fresh33_4`), attacker `com.cvefind.probe` uid 10179/10254 from the fresh guest. After a baseline private file existed, the probe overwrote it and read back `GCSTREAM-P2B-MARK-231641` in full. The initial fresh-device write failure `EBADF` is recorded as a negative precondition finding: `FSAdapter.saveContent` did not create a nonexistent file. - Evidence

## Impact

The attacker needs only the authority; on API 26+, `QP?URI=<base64url(file: URI)>` reaches any existing file the Ghost Commander uid can read or write. - The measured primitive is read/write in the victim's private files directory. No code execution or privilege escalation is claimed

## Preconditions / configuration

Attacker: an application installed on the device with no runtime permissions. Victim: none beyond installation of the application.

## Remediation

No fix released by the upstream project as of 2026-09-27; the vulnerable declaration is unchanged on the default branch commit that was checked. Recommended remediation: add an android:permission (or set android:exported="false" where external callers are not intended) to the affected component so that only the vendor's own applications can reach it.
