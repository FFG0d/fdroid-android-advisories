# Exported content provider in Bander Notepad allows unattended read and write of the user's notes

|---|---|

| **Published** | 2026-10-11 |

## Summary

bander.notepad version 12 for Android: Bander Notepad (`bander.notepad`): exported, permission-less `NoteProvider` allows unattended write and read of the user's notes — Sample, versionCode 12, SHA-256 `f10b04137a7d9968f65171d97c56d793e559a76584f388589f52def440cb7ae3`. - Manifest: `bander.provider.NoteProvider` declares authority `bander.Notepad`, no `android:permission`, no `android:exported`; the APK targets API 11, so pre-API 17 implicit export makes the provider reachable from other apps. - Dex contract: `bander/provider/NoteProvider` handles `notes` and exposes the columns `_id`, `title`, `body`, `created`, `cursor_position`, and `scroll_position`; insert routes through the app's private SQLite database Impact ceiling: The victim app must be launched once so its database exists; no permission or user confirmation is required for the provider read/write. - A zero-permission attacker can insert attacker-chosen note text and read existing notes. No code execution or privilege escalation is claimed

## Attack vector and prerequisites

Precondition: none beyond installation of the victim app with its note database created. No runtime permission for the caller, no user interaction, no prior state - only the provider authority.

## Proof of concept

Pass 1: emulator-5558, attacker `com.cvefind.probe2` uid 10220. After launching `bander.notepad/.NoteList` once, a baseline query returned zero rows; `inserturi` returned `content://bander.Notepad/notes/1`; the follow-up query returned `BANDER-P1-MARK-181500` and the app UI showed the same note. - Pass 2: same AVD after `pm clear`, attacker `com.cvefind.probe` uid 10254. After initializing the victim database and dismissing its first-run permission dialog, baseline query returned zero rows; `inserturi` returned `content://bander.Notepad/notes/1`; the read-back query returned `BANDER-P2-MARK-223818`, and shows it rendered in the app's note list.

## Preconditions / configuration

Attacker: an application installed on the device with no runtime permissions. Victim: the application installed with its note database created (it is created on first launch).

## Remediation

No fix released by the upstream project as of 2026-09-27; the vulnerable declaration is unchanged on the default branch commit that was checked. Recommended remediation: add an android:permission (or set android:exported="false" where external callers are not intended) to the affected component so that only the vendor's own applications can reach it.
